## 🎯 它解决什么问题

博客写好之后，同一篇内容要发到不同平台，每个平台的「正确形态」都不一样：

| 类型 | 平台 | 需要什么 |
| --- | --- | --- |
| 📝 原生支持 Markdown | 少数派、知乎 | 规整的 Markdown + 图片上传清单 |
| 🎨 需要排版美化 | 微信公众号 | 全内联样式的 HTML（微信不认 `<style>` / `class`） |
| 📋 富文本编辑器 | 豆瓣、B 站专栏、头条号、百家号 | 标准 HTML；清洗强度依次递增 |
| ✂️ 需要浓缩改写 | 小红书、推特/X、即刻、微博 | 按平台语气重写的短文案 + 配图卡片 |

前两类是**确定性转换**（不调用大模型、秒出、可复现），第三类是**大模型改写**。

三家富文本平台共用一套渲染，只按两处真实差异分叉：

- B 站专栏允许正文 `<a>`，头条和百家号会把链接清掉 → 于是抽成文末「参考链接」纯文本
- 代码块三家都不保证等宽 → 统一提示「粘贴后需检查格式」

`npm run check:platforms` 会断言头条/百家号的产物里**一个 `<a href>` 都不许有**。
这条错了页面上完全看不出来，直到粘进编辑器才发现链接全变死文字。

## 🔑 AI Key 怎么来

工具本身没有服务器，也没有中转。Key 存在**你自己的浏览器 localStorage**，请求从浏览器
直连服务商。

- ✅ 支持任何 **OpenAI 兼容**接口：DeepSeek / Kimi / 智谱 / 硅基流动 / 通义 / OpenAI
- ✅ 也支持自定义地址：本地 Ollama、one-api 中转都行
- ✅ 设置 → 选服务商 → 填 Key → 点「测试连接」（用 `max_tokens: 8` 做最小验证）→ 保存

> ⚠️ 换域名要留意跨域：服务商必须允许你的站点 Origin。DeepSeek 会回显请求方 Origin，
> 所以换到 `publish.hulatu.com` 依然能直连；换成白名单制的服务商则需要把域名加进去。

## 🧠 改写为什么是两段式

一开始是一步到位：把全文丢给模型，让它直接产出四个平台。结果很差 —— 模型只盯开头几段，
后半篇内容整体丢失，所谓「要点」也没有结构锚点，读起来是一堆散句。

现在是两段：

```
① 全文 ──按 ## 切节──▶ 每节 1–2 句摘要 + 全篇一句话      （中间产物，可逐条手改）
② 摘要 ──按平台重写──▶ 小红书 / 推特 / 即刻 / 微博 成品文案
```

这样做的收益：

| 收益 | 具体怎么做 |
| --- | --- |
| **覆盖可验证** | 要点数量 = 小节数量，漏掉一节会被校验打回，模型少给就本地补齐 |
| **空壳句判不合格** | 「本节介绍了……」「作者认为……」「综上所述」开头一律重写 |
| **结构可校验** | 小红书正文里没有 `· 小标题：一句话说明` 这种要点行就打回重来 |
| **只重跑需要的** | 摘要改完再生成；切换平台只跑第②段，不重复消耗 token |

## 🎨 公众号排版主题

12 套主题，四组。差别不只是换色 —— 标题形态、是否衬线、首行缩进、引用块、代码块明暗、
表格线条都是独立开关，所以同一篇文章在不同主题下是**结构**不同，不是换了件衣服。

| 组 | 主题 | 特征 |
| --- | --- | --- |
| 极简 | 纸白 / 素页 / 墨线 | 左竖线 / 零装饰 / 下划线标题 |
| 书卷 | 宋刻 / 米黄 / 铅字 | 衬线 + 首行缩进 + 居中标题 / 暖棕旧纸 / 报纸式粗横线 |
| 色块 | 靛蓝 / 序号 / 薄荷 | 标题带底色块 / 01·02 编号 / 浅绿圆角 |
| 商务 | 藏青 / 石墨 / 莫兰迪 | 深色代码块 / 无装饰标题 + 深色代码 / 低饱和豆沙色 |

选择器里的缩略图是用**真实渲染管线**跑出来的，不是示意图 —— 卡片上看到什么，
复制到公众号就是什么。

点顶栏的「更换」打开的是**主题墙**（弹层 + 全宽网格），不是横向滚动的窄条：列数由可用宽度
决定（宽屏 6 列，12 款两行放得下），缩略图宽度跟着列宽走（ResizeObserver 算缩放比），
不会出现「右边一片空、要横向拖」的情况。

<details>
<summary><b>➕ 怎么加一套新主题</b></summary>

在 `src/themes/wechat.ts` 里追加一个 `ThemeSpec`：

```ts
const myTheme = makeTheme({

  heading: 'underline',   // bar | plain | underline | center | block | index

  code: 'dark',           // light | dark

```

`npm run check:themes` 会把 109 篇文章 × 全部主题真渲染一遍，检查：

- 输出里没有 `class` / `id` / `<pre>`
- `style` 属性没被引号截断
- 字符数比基准主题涨幅不超过 20%
- 编号主题真的注入了 01/02

</details>

> 🕳️ **两个踩过的坑**
>
> - 微信会把 `::before` 伪元素整条剥掉 → H2 编号只能在渲染时注入真实 `<span>`
> - `style="..."` 里的 `font-family` 如果带双引号，属性会被提前闭合，后面所有声明全部失效 ——
>   表现为「只有第一条样式生效」，非常难查。**字体名一律用单引号。**

## 🖼 图片图注

Markdown 里**独立成段**的图片，会在图下方自动生成一行图注：居中、灰色、比正文小一号
（正文 16px → 图注 13px，字号按主题的正文字号算，永远小一档）。

图注取哪个名字，按这个顺序：

| 情况 | 图注 |
| --- | --- |
| `![10 月跑量](https://img.hulatu.com/post/UILBl6.jpg)` | `10 月跑量`（用 alt） |
| `![](/images/cover.png)` | `cover.png`（alt 为空才退回文件名） |
| `![](data:image/png;base64,...)` | 不生成图注 |

**为什么优先 alt 而不是文件名**：图床的 URL 里是 `UILBl6.jpg` 这种随机串，拿它当图注没有意义；
alt 才是作者写的那句话。只有当 alt 是空的，才认为文件名是作者自己起的、值得显示。

> 顺带修掉一个静默 bug：`markdown-it` 把图片的 alt 放在 `token.content`，**不在 attrs 里**。
> 之前只读 attrs，导致全文图片的说明文字在产物里一直是空的（少数派那条 Markdown 出口
> 会输出成 `![](url)`，图注也无从生成）。

实现上两个细节：

- 图注和图片是**两个并列块**，不是嵌套。`<p>` 里套 `<p>` 会被浏览器自动闭合，
  豆瓣那一路的 `text-align:center` 会直接失效。公众号用 `<section>`、标准 HTML 用 `<p>`，都并列。
- 站内「阅读预览」走另一套（markdown-it 渲染器规则），输出 `<figure>` + `<figcaption>`，
  样式在 `global.css` 里。两边比例一致，预览看到的就是粘出去的样子。

`npm run check:captions` 断言 25 条：alt 不再丢、图注在图下方、字号小于正文、颜色是低饱和灰、
`data:` 不产生图注、图文混排不误判、连续两张图各配一条、豆瓣产物里没有 `<p>` 套 `<p>`。

## 🖼 图片链路

md 里的链接是这个工具**唯一**的图片来源。图床归作者自己管（upic + Cloudflare R2、
imgbb、自己的对象存储都行）：不上传、不改写正文、不替你换地址。

工具只做「读完链接之后」的两件事：

| | 做什么 | 为什么 |
| --- | --- | --- |
| **体检** | 能不能取到 / 有没有防盗链 / 真实格式 / 多大 / 比例 | 图挂掉是**静默**的：粘到公众号裂一张，编辑器不报错 |
| **导出** | 按当前平台转成「后台上传时最不容易出问题」的形态，打包 zip | 公众号超 2 MB 容易转存失败、小红书首图要 3:4 |

### 为什么不做图床

早先这里有过一整套上传能力（四个适配器 + `/api/upload` + 服务端 token 校验）。删掉的理由：

- **它解决的是别人的问题**。作者已经用 upic 传好了，md 里就是 `https://img.hulatu.com/...`。
  再给一个上传入口，只是让同一个动作有两个入口。
- **它是唯一需要服务端的功能**。为了它得维护一个带 token 校验的公开上传接口，
  而其余所有能力都是纯前端。
- **它会让人以为图片归这个工具管**。一旦有「传图床」按钮，就会有人问
  「为什么这里传的图和我图床里的不一样」。

一个发布台如果连图床都要管，那它就成了另一个图床。

### 导出规则

只写两条，因为只有这两条有公开且稳定的依据：

| 平台 | 做什么 | 依据 |
| --- | --- | --- |
| 公众号 | 长边超 1920 缩、透明铺白、超 2 MB 压 | 正文图会被转存到 mmbiz CDN，超限容易失败；透明底会变黑 |
| 小红书 | 不是 3:4 的按中心裁 | 首图是 3:4 竖图，横图会被裁掉两边 |
| 其他 | 原样导出 | 没有公开的稳定上限，编一个只会让人以为查得比实际准 |

三条刻意的取舍：

**① 动图一律原样导出。** canvas 只能取第一帧，压了就是把动图变成静图 ——
这是静默的数据损坏，比交一张超标的原图坏得多。超限时清单里会写清原因和实际体积。

**② 扩展名按内容取，不按 URL 取。** 实测图床上 53 张 `.webp` 全是 JPEG 字节，
按 URL 命名会得到 `03.webp` 里装 JPEG，上传到按扩展名校验的地方就被拒。

**③ 不知道就不做。** 没量到体积就不说「要压」，没量到尺寸就不裁 ——
裁错比不裁糟得多。铺白底是唯一无条件执行的规则，因为它不依赖任何未知事实。

### 为什么转码必须走 blob

直接 `img.src = 'https://...'` 画到 canvas 上，canvas 会被跨域污染（tainted），
`toBlob()` 直接抛 `SecurityError` —— 成不成取决于图床开没开 CORS，而自建图床
（含 R2 自定义域名）默认不发 `Access-Control-Allow-Origin`。

所以先 `fetch` 拿到 blob，再 `URL.createObjectURL(blob)`：blob URL 与页面同源，
画进去不会污染。取 blob 这一步可以退到同源代理，整条链路都不依赖图床配置。

### zip 里有什么

```
01.jpg  02.jpg  …  图片清单.txt
```

清单不是可有可无的：解开 zip 只看文件名，没法知道哪张对应文中哪个位置，
传到平台后台就会传错顺序。清单逐张写：原文说明、原图地址、做了什么处理、没做什么。

`npm run check:imgaudit` 和 `check:imgexport` 测的都是纯函数（不碰网络、不碰 canvas）：
判定顺序、防盗链与打不开的分家、动图为什么不动、3% 容差、扩展名按内容取、
清单里不许出现 `undefined`。

## 🔖 脚注与 Markdown 保真

Hugo 的 `[^1]` 脚注在两个出口里各有归宿：公众号 / 豆瓣这类 HTML 出口在文末列「注释」区；
少数派 / 知乎走 Markdown 出口时原样保留 `[^1]` 与 `[^1]: …`，交给平台自己渲染。

这里踩过三个坑，都已修掉，`npm run check:roundtrip` 各有一条断言守着：

| 坑 | 表现 | 根因 |
| --- | --- | --- |
| 引用和定义编号不是一套 | Markdown 出口里引用写成 `[^0]`、定义是 `[^1]:`，脚注在平台上直接失效 | `footnote_ref` 的 `meta.id` 是内部序号，`meta.label` 才是作者写的编号 |
| 没人引用的定义整块消失 | 作者漏写一处引用，那段参考书目在产物里一个字都不剩（预览里也一样） | `markdown-it-footnote` 只在「有引用成立」时才吐出定义块，否则连 token 都不生成 |
| 行首的 `#` `-` `>` `1.` 不转义 | 一篇讲 Markdown 语法的文章，列表项内容导出后变成了标题 | 行内转义（`* _ [ ]` 反引号）管不到行首 |

第三条不属脚注，但同样是「往返」暴露的：一次 md → IR → md 之后语义就变了。
现在定义若落单，会保留在文末并给一条提示（「有 N 条脚注定义没有对应的引用」），
不静默吞掉——转换器丢内容比排版难看严重得多。

`npm run check:roundtrip` 除了逐条断言上面三条，还拿**全部真实文章**整篇跑两轮
md → IR → md → IR，比较块类型序列和汉字序列，两轮必须完全一致。

## 📇 配图卡片

一套图 = **封面 + 每个 `##` 小节一张 + 结尾**。按小节出图而不是只出四张，是因为图集要
「一图一件事」：一张图塞四个要点，读者在手机上扫过去什么都记不住；一节一张，图集本身
就是一份能滑完的提纲。

| 版式 | 内容 | 正文来源 |
| --- | --- | --- |
| 封面 | 标题 + 摘要 | 元信息 |
| 小节 | 小节标题 + 本节摘要 | AI 章节摘要（已校对）→ 本地「本节前两句」兜底 |
| 结尾 | 总结 + 标签 | 元信息 |

- 🔢 每张卡右上角有 `03 / 08` 页码，整套连起来读时知道进度
- 🧱 四张版式共用同一个 `Shell` 骨架（同边距、同页脚基线、同分隔线），装饰元素全部锚在
  正文区之外，结构上不可能压到文字
- 📐 三种比例**按比例重排而不是整体缩放**：3:4 竖图 1080×1440、1:1 方图 1280×1280、
  16:9 横版封面 1920×1080。缩放的话 16:9 的字会小一半
- 🖱️ 卡片可拖拽排序，拖完页码自动重排；可单张下载，也可整包 zip（按比例分子目录）
- ➕ 「加一张卡」可以补金句 / 要点 / 小节 / 封面 / 结尾；改过的卡不会被新摘要覆盖

`npm run check:cards` 会用全部真实文章跑一遍出图逻辑，检查卡片数、页码连续性、
摘要非空且不超过画布容量（118 字）、标题不残留 Hugo 锚点。

## ✅ 发布前的几件小事

复制之前最容易忘掉的事，入口都在主标题右边和顶栏。

| 入口 | 作用 | 关键设计 |
| --- | --- | --- |
| 📋 **台账** `台账 3/11` | 记录发到哪了 | 复制即标记 + 记时间，链接事后补；侧栏出现绿勾 |
| 🔍 **标题与标签** `标题 8` | 一次 8 个角度 | 至少 3 条在 20 字内；没 Key 时本地重排、不新增事实 |
| 🔗 **公众号文末** `文末 2/3` | 关注引导 / 往期推荐 / 版权 | 配色从当前主题抠，不另配一套 |
| 🛡️ **合规检查** `● 检查通过` | 本地词表 + 正则 | 按平台分规则，命中给原句 + 改法 |
| 🖼️ **图片清单** `图片 12` | 按出现顺序列出所有图 | 两个页签：**体检**（能不能取到 / 有没有防盗链 / 格式对不对 / 多大）、**导出**（按当前平台压体积、裁比例，打包 `01.jpg` + 清单） |

几个值得说的取舍：

- **导出为什么要一个代理**：把图塞进 zip 得先 `fetch` 成 Blob，而跨域 `fetch`
  要求对方返回 `Access-Control-Allow-Origin`。图床一般只服务 `<img>`、不发这个头 ——
  于是预览里 16 张图全都正常，点「导出」却 16 张全红「失败」。
  `functions/api/img.ts` 做同源转发补上这个头，**只放行 `ALLOWED_HOSTS` 里的域名**
  （开放代理会被拿去刷流量）；换图床时往那个数组里加一行即可。
  代理不可用时（本地 `vite dev` 没跑 Functions）自动退回「逐张打开原图另存」。
- **导出不改正文**：图还是你图床上的那几张，zip 只是同一批图的本地副本。
  想换地址就换，工具不会跟着改 md。

- **体检为什么要让服务端代发一次请求**：判断「别的站引用会不会被拒」只能靠
  **带第三方 Referer 去取一次图**，而浏览器根本改不了 Referer —— `referrerPolicy`
  只有 `no-referrer / same-origin / origin / strict-origin` 几个值，写不成
  `mp.weixin.qq.com`。所以 `/api/img?probe=1` 让 Worker 代发，而且**发两次**：
  不带 Referer 一次（问「图还在不在、多大、什么格式」）、带第三方 Referer 一次
  （问「别的站引用会不会被拒」）。`hotlink` 的判定是
  `foreign === 403 && plain === 200` —— 少这个与条件，一张 404 的图会被报成防盗链，
  让人去 Cloudflare 后台找一个根本不存在的问题。

- **体检宁可说「没查全」也不说「没问题」**：本地没跑 Functions → 明说「体积和格式还没查」；
  跑了但量不到体积（取图被拒）→ 明说「其中 N 张量不到体积」。一句假的「全部正常」
  比不报更坏，因为人不会再去看第二遍。

- **「打不开」和「防盗链」是两条独立的 if，不是 else-if**：一张图可以既取不到又被拦，
  两条都报才说得清；更要紧的是「取得到、只是别的站引用被拒」这个最常见的情况 ——
  它挂在 `loaded === true` 上，塞进 else 里就永远进不去。

- **往期推荐刻意不渲染 `<a>`**：未认证公众号正文的外链会被整条剥离，给一个会被吃掉的链接
  比不给更糟。默认配置平均只增加 442 字符，`npm run check:tail` 守住「不把任何一篇顶超限」。
- **词表收得很窄**：「最好」「唯一」「绝对」看着像极限词，但「最好的朋友」是正常中文，
  全收进来会让 61% 的文章都报警，用户第二次就不看了。现在 109 篇的命中率 14%、
  平均每篇 0.17 处，`npm run check:compliance` 守住这个量级。
- **标题单独一路生成**：标题是跨平台共用资产，塞在小红书正文里顺带产出等于没得选。

## 📝 草稿箱与复盘

**草稿箱**（顶栏 `草稿 4`）

花两次大模型调用把四个平台的文案都生成好了，手一滑关掉标签页 —— 全没了。所以这里存的是
「重新生成很贵的东西」：摘要、四平台文案、标题候选，连正文（含 front matter）一起存，
否则恢复回来只剩一堆没正文的文案。

- 💾 自动保存，延迟 800ms，没有保存按钮（逐字写盘会把输入卡出明显延迟）
- 🚫 流式文本不落盘：`streaming` 每 100ms 涨一次，写进去既没用又吃配额
- 🗑️ 容量满了淘汰最旧的，**绝不牺牲刚写的那篇**；单篇超配额返回 false，不抛异常
- 🔗 重新导入同一篇时，若正文指纹（小节数 + 字数）没变，自动接回草稿里的 AI 产物；
  结构变了就不套 —— 否则 AI 面板显示 N 节、摘要只有 M 条，看着像坏了

**复盘**（顶栏 `复盘`）

11 个平台没有一家给个人号开数据接口，自动抓就得写爬虫，维护成本远高于收益。
所以只做两件事：**填得快、看得清**。

- 「本篇」把各平台后台的数字抄进来：阅读 / 点赞 / 评论 / 收藏，四格横排、数字键盘
- 「全部」跨篇对比，按阅读倒序，给的是**相对量** —— 互动率，而不是绝对数字。
  3 万阅读在微博和小红书是完全不同的量级
- 阅读为 0 或没填时互动率显示「—」而不是 0%：0% 会被读成「发了没人理」，
  和「还没数据」是完全相反的结论

## 🚫 为什么没有一键发到公众号

考虑过，放弃了。公众号没有能从浏览器直接调的接口，要做就得自己架一台中转服务，
成本不在代码上：

| 约束 | 后果 |
| --- | --- |
| `AppSecret` 不能进前端 | 打包后的 JS 谁都能读，泄露等于把公众号交出去 |
| `access_token` 要缓存统一刷新 | 2 小时过期，多端各自刷新会互相顶掉，表现为随机 `40001` |
| IP 白名单 | 微信要求调用方 IP 固定，浏览器和 Serverless 都没有固定出口 IP |
| CORS | `api.weixin.qq.com` 不返回跨域头，浏览器读不到响应 |

也就是说，为了省掉「复制 → 粘贴 → 补封面」这十几秒，得长期维护一台有固定 IP 的机器、
一个 token 缓存、一套错误码对照。而它换来的只是把同一段富文本从剪贴板搬到接口，
中间没有任何一步是这个工具独有的能力。

**复制粘贴已经够用，不值得为此多一个线上服务。**

### 🔗 折中方案：复制后把发布页打开

完全不碰账号，只把「找到后台入口」这一步省掉。操作条右侧勾上「复制后自动打开」，
复制成功时顺手把该平台的后台页面开在一个新标签里，切过去直接粘贴。
旁边还有一个独立入口「打开 XX 发布页 ↗」—— 不复制也能直接跳过去，它是个普通链接
（中键、右键复制地址、悬停看目标都能用），不依赖 `window.open`，因此不受弹窗拦截影响。

实现上只有一个坑值得记：`window.open` 必须在用户点击的**同一个任务**里调用，一旦中间夹了
`await`（复制本身是异步的），浏览器就判定成非用户发起，直接拦掉。所以是先同步开一个
`about:blank`，复制成功后再 `location.replace()` 过去，失败就关掉这个空白页。

地址表在 `src/core/publish.ts`，11 个平台各一条，`check-platforms` 会校验覆盖完整、
全是 https、没有重复。

**不做的事很明确**：不碰账号密码、不填表、不点发布。这几个平台都没有给个人开发布接口，
脚本代发既违反条款又有封号风险，而收益只是省一次粘贴。

### 📦 折中方案之二：导出全平台

操作条上的「导出全平台」把这篇文章在 7 个转换平台上的产物打成一个 zip：

```
01-少数派-slug.md        05-B 站专栏-slug.html
02-知乎-slug.md          06-头条号-slug.html
03-公众号-slug.html      07-百家号-slug.html
04-豆瓣-slug.html
```

用途是归档、备份、换电脑继续发，以及「先看一眼每个平台长什么样」。
不做批量复制 —— 剪贴板只有一份，11 个平台还是得一个个来。

两个实现细节：

- **只导转换平台**：AI 改写的 4 个平台要先调模型，产物不确定；配图是 PNG，走自己的入口。
  被隐藏的平台也不导，隐藏本来就表示「我不发这家」。
- **7 个平台其实只有 4 种产物**：少数派与知乎是同一份 Markdown，豆瓣与 B 站专栏、
  头条号与百家号各自字节相同 —— 它们本来就共用一套渲染，差别只在提示文案。
  仍然一个平台一个文件，是为了解压后一眼知道哪个给哪家。

## 🌐 网络层

所有大模型请求都直接从这里发往使用者自己填的服务商，中间没有服务器。正因如此，
健壮性得自己兜住 —— 线上没有一层网关帮你重试。

**⏱️ 三段超时**（`src/ai/provider.ts`）

| 阶段 | 上限 | 挡的是什么 |
| --- | --- | --- |
| 首字节 | 45 秒 | 连上了但不吐字：网关挂起、代理缓冲、服务端排队 |
| 空闲 | 30 秒 | 已经开始吐字，两帧之间断了 |

用「空闲超时」而不是一刀切的 `AbortSignal.timeout`：长文生成慢但持续有输出是正常的，
一刀切会把它们误杀。收到任何字节（含 `: keep-alive` 心跳）都重置计时。

**🔁 只重试值得重试的**

| 结果 | 处理 |
| --- | --- |
| 超时 / 429 / 5xx / `Failed to fetch` | 退避重试，最多 3 次 |
| 401 / 402 / 403 / 404 / 400 | 立刻失败，重试一百次也一样 |
| 用户点了「停止」 | 一次都不重试 |

**⚡ 并发**

- 图片导出并发 3（浏览器同域允许 6，取 3 是不想被图床当成爬虫）
- 四个平台生成并发 2，撞上 429 自动退回串行

**📉 体积**

jszip 和 html-to-image 改成动态 `import()` —— 只有点「导出」才用得上，首屏 JS 约
**190 KB gzip**。另外保存 endpoint 后会插一条 `preconnect`，把 DNS + TCP + TLS 提前到
用户读界面的时候。

**📴 离线**

`public/sw.js` 是个很克制的 Service Worker：导航请求走 network-first（在线永远拿最新 HTML，
不会卡在旧版本），`/assets/*` 走 cache-first（文件名带内容哈希，缓存不可能命中错的）。
断网时还能打开界面、看到草稿箱；但生成不了 —— 那需要网络，没得绕。

## 📦 部署

托管在 **Cloudflare Pages**，域名 `publish.hulatu.com`（和主站 `hulatu.com` 同一个
Cloudflare 账号，证书和 DNS 都在那里统一管）。

Cloudflare 从 GitHub 仓库 `hulatu/Publishing_Platform` 拉代码构建：

| 配置项 | 值 |
| --- | --- |
| 生产分支 | `main` |
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| 环境变量 | `NODE_VERSION=22` |

构建用相对路径（`base: './'`），产物既能挂根域名也能挂子路径，换托管不用改配置。
`public/_headers` 给带哈希的 `/assets/*` 上了永久缓存，入口 HTML 不缓存。

GitHub 上的 `.github/workflows/ci.yml` **只做校验不做发布**：push 时跑类型检查、
`npm run check:fixtures`、`npm run build`，坏了在 GitHub 上直接看红叉，
不用等 Cloudflare 构建失败才发现。

> GitHub Actions 跑回归（校验）。所以**可能出现「Actions 红叉但网站照常更新」** ——
> 那说明代码能构建、但某条断言没过，别当成噪音直接忽略。

## 🎛 视觉口径

七条硬规矩。前六条 `npm run check:contrast` 全部守着，改样式时别绕过；第七条靠肉眼，因为它没有阈值。

**1. 文字色对底色一律 ≥ 4.5:1**

全站文字色（`--ink` / `--ink-soft` / `--ink-muted` / `--accent` / `--ok` / `--warn` / `--error`）
对 9 个底色（`--bg` / `--sidebar-bg` / `--main-bg` / `--panel` / `--panel-soft` / `--panel-inset`
+ 三档状态柔和底 `--ok-soft` / `--warn-soft` / `--error-soft`）
共 126 组，两套主题全部达标。`npm run check:contrast` 直接读 `global.css` 的 token 现算，改坏了会红。

> 三档状态柔和底是最后补进来的：提示条拿它们当背景、把正文色压在上面写，
> 但以前只量了六个页面底。`--ok-soft` 是这一轮新加的「查完没事」结论条，
> 加进清单之前它只是「看着浅」——**没被量过的底色，等于没被定过**。

> `--ink-muted` 曾经是 `#8f887f`，在暖纸底上只有 3.05:1 —— 而它扛着 hint、统计条标签、
> 侧栏平台说明这些 10~11.5px 的小字。肉眼只觉得「有点糊」，说不出差多少，于是就这么糊着。
> 现在浅色是 `#6f6759`（最差 4.66:1）、深色是 `#a29a8d`（最差 5.95:1）。
> 同理 `--warn` 从 `#a9761b` 压到 `#8a5e15`、`--ok` 从 `#2f7d5d` 压到 `#2c7558`。

**2. 预览区只有一个列宽**

提示条、折叠清单、源码卡片、富文本预览、Markdown 预览、改写/配图面板全吃 `--read-w`。
原先分别是 780 / 780 / 780 / 720 / 760 / 820 —— 同一列里三个宽度，往下滚的时候左右边缘一跳一跳的。
`check:contrast` 会顺带断言这六条规则里没有硬编码宽度。

**3. 正文行宽不随屏幕涨**

`--read-w` 在 1440 是 780px（16px 中文约 44 字/行，已经是舒适上限），
到 1600px 以上放宽到 900px —— 但多出来的宽度全进卡片内边距，**正文仍是 720px**。
宽屏下让卡片跟着长是像「一页纸」，让行宽跟着长就是逼人转头读。

**4. 字号只走 8 档阶梯**

`--fs-2xs` 10.5 / `--fs-xs` 11.5 / `--fs-sm` 12.5 / `--fs-md` 14 / `--fs-lg` 16 /
`--fs-xl` 18 / `--fs-2xl` 20 / `--fs-3xl` 26。

原先散着 18 个值，`9 / 9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13` 全挤在 4px 里。
**半像素的差别看不出层级，只让人看到参差** —— 同一个侧栏里，分组标题 10、平台说明 10.5、
平台名 12.5、角标 9、字母块 11.5，五个尺寸谁也说不清谁更重要。
唯一不走阶梯的是折叠箭头 ▶ 的 `8px`：那是图标字形，跟着 10.5 走反而比旁边的字更重。

**5. 圆角只走 5 档 + 胶囊 + 正圆**

`--radius-xs` 4 / `--radius-sm` 6 / `--radius` 9 / `--radius-lg` 13 / `--radius-xl` 18 /
`--radius-pill` 999 / `50%`。另外 `1px`、`2px` 是发丝线和指示条，不算圆角。
原先有 `1/2/3/4/5/6/7/8/10/20/999` 十一种写法，光侧栏里就并排放着五个不同的圆角，凑近看就是毛边。

**6. 同一个选择器不许写两遍**

`.check-row` 曾经在文件里出现两次（`gap: 8px` 一份、`gap: 7px` 一份，隔了 660 行），
后一份整条盖掉前一份 —— 「8px」这个值从来没生效过，而 `margin-top: 12px`
对每个调用方都生效，连不需要它的地方都得在行内 style 里手动改回来。
CSS 不报错、构建不警告，只能靠断言守。媒体查询里的覆盖不算重复。

**7. 网格列宽按内容定，不按「好看」定**

`.img-grid` 原来是 `minmax(148px, 1fr)` —— 760px 的面板里排四列，每张卡片的事实行只剩 153px，
而最长的那行 `1920×1054 · 3.1 MB · GIF` 要 157px：**正好差 4px，把格式截成「G…」**。
格式恰恰是这一行最要紧的信息（`.webp` 里装的其实是 JPEG，就是这么看出来的）。
改成 184px（三列、232px）后富余 57px，顺手缩略图也大了一圈。
卡片变小只是看得少一点，**截断是真的少了一条信息** —— 有 `ellipsis` 兜底不代表可以靠它兜底。

## 💻 本地开发

```bash
npm run dev             # 开发服务器
npm run typecheck       # 只做类型检查
npm run check           # 全部回归（扫 ~/Blog/content/posts 的 109 篇真实文章）
npm run check:contrast  # 对比度 + 预览列宽 + 字号/圆角阶梯 + 重复选择器
npm run check:fixtures  # 同一条回归，但用仓库内 scripts/fixtures 的 4 篇样本
npm run build           # 类型检查 + 生产构建到 dist/
npm run preview         # 预览构建产物
```

**提交前跑 `npm run check:fixtures`。** GitHub Actions 跑的就是这一条命令。

<details>
<summary><b>❗ 为什么本地和 CI 要用同一套样本</b></summary>

两套样本不是一回事：本地 `check` 读你机器上 Hugo 博客的 109 篇文章，覆盖面最好；
CI 里没有那个目录，只能读仓库自带的 4 篇 fixtures。

样本不同 → 结果可能不同，曾经出现过「本地全绿、CI 每次推送都红」的情况：
`fixture-html.md` 在编号主题下字符涨 22.3%，撞上 20% 的阈值，而 109 篇真实文章里没有这篇。

现在 CI 用 `check:fixtures`，和本地这条命令完全一致，**红就是真红**。

</details>

## 🧾 已知取舍

- 四个平台一起生成是并发 2，约一分钟；撞上限流会自动退回串行
- 摘要最多切 12 节，超长文章会把相邻小节省并，合并过的节会标注「含合并小节」
- 公众号正文上限 20000 字（微信编辑器按字数算），超了会提示按 H2 拆篇，不截断内容
- 顶部 `HTML 字符数` 只反映粘贴体积，不参与超限判定 —— 内联样式会让 1 万字的稿子膨胀到 5 万字符
- 卡片导出用 `html-to-image`，不能引用外链图片（会触发 CORS）
- Unsplash 封面图要自己申请 Access Key（免费），demo 应用每小时 50 次；中文关键词命中率低，面板会提示换英文
- 图片只读不写：图床上的图不会被改名、删除、重传；导出只是本地副本，正文链接一个字节都不动
- 导出全在浏览器里转，图片不出本机；代价是超大图（4000 万像素以上）会先缩到安全尺寸再处理
- 草稿箱上限 20 篇，超了淘汰最旧的。localStorage 只有 5MB，一篇带 AI 文案的草稿约 30–60KB
- 复盘数据全部手填：11 个平台没有一家给个人号开数据接口，自动抓就得写爬虫
- 离线只能打开界面和草稿箱；懒加载的 jszip 不在预缓存里，断网点「导出」会失败
- 隐藏平台只影响侧栏显示，批量生成仍会跑全部四个改写平台
